## Introduction

Every day, countless APIs are compromised by one simple mistake: **trusting user input**. From malformed JSON to injection attacks, the attack surface is enormous when we assume incoming data is safe.

## The problem: user input is dangerous

When data comes from outside your system, it can be malformed (invalid JSON, wrong types), malicious (SQL injection, XSS), or simply unexpected (missing fields, wrong formats).

```javascript
// ❌ VULNERABLE CODE
app.post("/api/users", (req, res) => {
  const { name, age, email } = req.body;

  // No validation - disaster waiting to happen
  db.query(
    `INSERT INTO users (name, age, email) VALUES ('${name}', ${age}, '${email}')`
  );

  res.json({ success: true });
});
```

A simple `name: "John', 'admin'); DROP TABLE users; --"` is enough to compromise the database.

## The solution: validate with Zod

**Parsing**, **validation**, and **sanitization** are three different things: converting raw data, checking it follows rules, then cleaning it to make it safe. [Zod](https://zod.dev/) does all three in a single TypeScript-first library.

```javascript
import { z } from "zod";

const userSchema = z.object({
  name: z.string().min(2).max(50),
  age: z.number().min(0).max(120),
  email: z.string().email(),
});

// ✅ SECURE CODE
app.post("/api/users", (req, res) => {
  try {
    const validatedData = userSchema.parse(req.body);

    db.query("INSERT INTO users (name, age, email) VALUES (?, ?, ?)", [
      validatedData.name,
      validatedData.age,
      validatedData.email,
    ]);

    res.json({ success: true, user: validatedData });
  } catch (error) {
    if (error instanceof z.ZodError) {
      return res.status(400).json({ error: "Validation failed" });
    }
    res.status(500).json({ error: "Internal server error" });
  }
});
```

This one approach prevents SQL injection (thanks to parameterized queries), type confusion (Zod enforces expected types), and buffer overflows (`.max()` limits string length).

## Best practices

- **Validate everything**: body, params, query, headers — not just the body
- **Never trust the frontend**: backend validation is non-negotiable, even if the frontend already validates
- **Use parameterized queries**: `db.query("... WHERE name = ?", [name])` instead of string concatenation
- **Centralize schemas** in a dedicated folder to reuse them across routes

## 🔑 Key takeaways

- **Never trust user input** - always validate on the backend
- **One validation library** like Zod covers most cases
- **Parameterized queries** to prevent SQL injection
- **Clear error messages** to help with debugging
